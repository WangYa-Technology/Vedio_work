## 二、H3 视频模板：接口层改造明细

方法论正文（镜头语言、17.x 术语库、情绪强度分级、动作链连续性、六字段结构、四类示例的镜头结构、自检清单）**一字未动**；仅改动以下接口层内容：

| # | 改动点 | 原文（字字动画口径） | 改后（漫橙映画口径） | 原因 |
| --- | --- | --- | --- | --- |
| 1 | 输入信息 | `{{角色信息}}/{{场景信息}}/{{物品信息}}/{{前面文案}}/{{前面分镜:2}}/{{后面分镜:2}}/{{输入文案}}` 占位符 | 指向项目实际注入的 JSON：`segments[].referenceMap / references / shotFacts / videoDescription / previousPrompt / duration`、`narrativeContext`、`contract.artStyle / visualStyleManual` | 项目不替换 `{{}}`，数据以 JSON 从 user 侧注入 |
| 2 | 映射写法 | `@角色名`（按名字映射） | `@图N：名称（类型）`（来自 referenceMap，片段内独立编号） | 项目按位置映射，H3 契约按 `@图N` 正则校验 |
| 3 | `<Subject N>` 绑定 | `bound to @场景映射名称` | `from @图N（场景名称）`，与项目追加协议一致 | 同上 |
| 4 | 输出协议 | 双字段（图片提示词 + 视频提示词）+ 三个分隔符 `_::~OUTPUT_START/_FIELD/_END::~_` + 硬性校验 | 删除；改为「输出方式以调用端追加的模型协议与批量规则为准，只产出视频提示词正文（图片提示词由分镜图环节单独生成）」 | 项目要求工具调用 `resultTool` 返回 `{trackId, prompt}`，不接受自定义分隔符 |
| 5 | 图片提示词口径 | 「提示词分工」含图片提示词字段、`prompt 的【人物/主体】字段` | 改为对 video_prompt / subject_definitions 的要求 | 该字段在项目中由另一环节生成，已删除 |
| 6 | 旧工具字段引用 | 「排除性内容移交字字动画负面提示词字段」等 4 处 | 改为「由调用端约束与校验承载（项目视频链路无负面提示词字段）」 | 项目视频生成链路没有负面提示词字段 |
| 7 | 台词标点 | `<d> 内标点按官方规则规范化（只保留 , . ? !）` | `<d> 内台词与标点必须与输入文案逐字一致（含省略号、破折号）` | 项目契约按输入逐字比对校验，自行规范化会判失败 |
| 8 | 单条/双字段残留 | 「一次只返回一组完整双字段」 | 「每个片段只返回一条完整的视频提示词」 | 与第 4 条一致 |
| 9 | 结构预检 | 「检查三个外层分隔符各一次…末镜实际覆盖至12秒」 | 「检查六字段顺序…末镜实际覆盖至输入片段时长」 | 分隔符已移除；时长以输入为准 |
| 10 | 时长口径 | （无） | 输出格式处新增一行：【时长口径】12 秒为默认参考，实际以输入 `duration / h3CutTimestamp` 为准 | 项目 H3 契约按片段真实时长校验累计切镜时间 |
| 11 | 示例映射写法 | 示例中 `(@名称) in <Picture N>` | `(@图N：名称) in <Picture N>`（N 取自同行 Picture 编号） | 与项目映射约定一致 |
| 12 | 文件头修订说明 | 「仍采用原双字段协议…三个程序分隔符均保留」 | 「采用调用端的工具调用（resultTool）协议…原双字段协议与三个分隔符按项目接口协议移除」 | 避免自相矛盾误导模型 |

**保留未动**：文件头版本说明、规则优先级、素材前置检查、模式边界、上下文权限、输入文案规则、生成规则 1–39、情绪分级 5.x、动作链、17.1–17.8 全部词库、重要说明、四个输出示例的镜头内容与六字段正文、各字段级写作规范。

## 三、三个提取模板：拆成两部分落位

### 1）提取规则 → 内置「剧本资产提取」模板

**接口层适配**：
- 输出方式改为项目要求的 `resultTool` 工具调用，字段限定 `{ name, desc, type(role/scene/tool), scriptIds }`；
- **不再要求 `prompt` 字段**（项目 schema 无此字段，原先写了也会被丢弃）；英文图片提示词由下游「图片提示词推理」环节单独生成；
- 三个模板的细节字段（分类/材质/主色调/尺寸/状态/光影/空间结构/关键陈设）**压缩进 30–80 字的 `desc`**：角色 = 性别+年龄+体态+五官骨相+发型+标志性服饰+气质；场景 = 空间类型+时间气象+光影+色调+材质+空间结构+固定陈设；道具 = 分类+材质+色调+**绝对公制尺寸**+状态+外观结构；
- 保留原有全部提取规则：穷尽性、一人一条目（禁止按服装拆分）、场景/道具的状态拆分、命名规范（场景 ≥6 字「空间+状态」、道具 ≥4 字「物品+特征」）、去人像约束（场景/道具严禁人物、人体、佩戴手持与**人名**，归属只写身份代称）、别名归一化（取最常用称呼为 `name`）、已有资产走 `existingAssetRefs`。

### 2）生图提示词规范 → 新增图片提示词模板

「H3仿真人资产生图规范（角色/场景/道具）」，使用项目变量 `{{名称}}/{{类型}}/{{描述}}/{{当前提示词}}`，按 `{{类型}}` 三态分支：

| 类型 | 结构要点（来自三个 docx） |
| --- | --- |
| 角色 role | 四段结构【人物基本特征】【五官与头部特写细节】【标准着装（全视角一致）】【画面要求】；Character Model Sheet 四视图（正面/侧面/背面全身 + 面部高精特写）；纯净白或极简浅灰背景；多视角比例统一 |
| 场景 scene | 纯环境空镜、**禁止人物与活动踪迹**；空间类型/时间气象/光影氛围/主导色调/材质质感/空间构图/固定陈设；保留英文兜底格式串 |
| 道具 tool | 材质构成/主色调/**绝对公制尺寸**（严禁“巴掌大”“手持”）/物理状态/几何与外观细节；**禁止人体、佩戴、手持** |

**通用硬性要求**：只输出一条提示词正文；**风格中立**（画风由项目下游注入，不写死画风词）；**画面零文字污染**（不得画出资产名称、标签、水印）——这条同时解决了此前“图上出现角色名”的问题。

### 3）被 schema 丢弃字段的处理

| 原字段 | 处理方式 |
| --- | --- |
| `aliases`（别名） | 只用于内部归一化，取最常用称呼作为 `name`；不单列 |
| `image_prompt` / `description` | 移到图片提示词模板（落位 2） |
| `negative_prompt` | 转为各资产类型的自然语言排除约束一行（项目无按资产的负向字段；项目级 `negativePrompt` 仍会在图片生成时自动追加） |
| `size` / `material` / `color` / `condition` 等 | 压缩进 `desc` |

## 四、使用前提与注意事项

1. **片段时长**：模板方法论保留「12 秒分镜组」表述。项目 H3 契约按片段真实 `duration` 校验各镜累计切镜时间，因此**请把项目里的片段时长设为 12 秒**（当前视频模型 `minimax_h3_lightx2v_v5_15s` 支持 5–15 秒任意值）。若片段不是 12 秒，模板已加【时长口径】说明「以输入 duration / h3CutTimestamp 为准」，但为获得最一致的结果，建议统一 12 秒。
2. **适用模型**：模板内容为 MiniMax H3 Ref2VA 六字段协议，请在**视频模型为 MiniMax H3 系列、且模式为多参考（imageReference）**时选用。若切到基础模式（纯文本/首尾帧），应改用对应三字段模板。
3. **画风**：模板示例与兜底表述为「写实真人实拍质感」，与项目画风 `3D_realistic_cinematic`（写实电影级 3D）一致；若某项目使用 2D/动漫画风，需另做一份去真人化的模板。
4. **台词标点**：`<d>` 内台词必须与输入逐字一致（含省略号、破折号），不要按其他工具的规范自行删改标点。
5. **负面提示词**：视频链路没有负面提示词字段；字幕、配乐等排除性要求由系统的契约校验处理，不需要（也不应）写进提示词正文。
6. **分镜图提示词**：由「分镜图/资产图提示词」环节单独生成，本 H3 模板不再输出图片提示词。

## 五、工程实现与生效方式

| 环节 | 位置 |
| --- | --- |
| H3 视频模板常量 | `Toonflow-app/src/constants/h3VideoPromptTemplate.ts` |
| 图片提示词模板常量 | `Toonflow-app/src/constants/assetImagePromptTemplate.ts` |
| 提取规则常量 | `Toonflow-app/src/constants/assetExtractionPromptTemplate.ts` |
| 启动同步（幂等） | `Toonflow-app/src/lib/syncPromptTemplates.ts`（由 `src/utils/db.ts` 在 `syncVideoPromptDefaults` 之后调用） |
| 种子同步 | `src/lib/initDB.ts`（新库初始化）、`src/lib/fixDB.ts`（初始化时覆盖内置模板 data；已限定不覆盖用户模板） |
| 备份 | `Toonflow-app/data/backups/o_prompt_backup_2026-09-26T10-35-52-891Z.json`（全部模板原始行）、`data/backups/scriptAssetExtraction_id2_source.txt`（原提取模板全文） |

**生效方式**：模板存于数据库，**改完即用，无需重启**；本模板由源码常量同步写入，修改模板内容需改常量并重启（或在设置页直接编辑 `useData`）。

**幂等与覆盖规则**：两个新模板仅在 id 不存在时插入；提取规则仅在 `useData` 为空时写入。因此你在设置页所做的修改不会被启动流程覆盖；反之，若删除这两个模板，下次启动会自动恢复为常量中的原始内容。

**回滚方式**：
- 单个模板：设置 → 提示词管理 中删除或改回；
- 全部回滚：用备份 JSON 恢复 `o_prompt` 对应行（提取模板恢复 `data` 与清空 `useData` 即可回到旧版行为）。
