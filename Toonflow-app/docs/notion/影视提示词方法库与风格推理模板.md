## 一、已提炼的方法

### 1. 先锁定视觉锚点，再生成多视角

适用：场景一致性、角色三视图、首尾帧、参考图生视频。

- 先提取主体、服装/道具、环境结构、光源方向、色调和媒介质感。
- 把共同特征写成不可改动的基础锚点，后续只改变机位、景别或动作。
- 多视角输出要区分水平角度、垂直角度和景别，避免只换几个形容词。
- 参考图负责身份和场景一致性，文字只描述本镜头新增的动作、视角与节奏。

### 2. 用可拍摄的动作替代抽象情绪

适用：影视分镜、AI 视频提示词、漫剧镜头。

- “悲伤/紧张/震撼”必须落到视线、停顿、肩颈、手部、步伐、构图、光影或声音。
- 一个镜头只保留一个主动作，必要时按“起势 → 作用 → 反应”拆解。
- 运镜使用具体术语：推、拉、摇、移、跟、环绕、升降；不要写“镜头移动”。

### 3. 用时间轴组织短视频节奏

适用：Seedance 2.0、15 秒短片、广告和漫剧。

- 开头先建立场景或冲突，中段推进，后段完成高潮、反转或悬念。
- 每个时间段同时写景别、运镜、主体动作、环境变化和声音。
- 时长、镜头数量和动作复杂度相互约束，不把多个独立视频误合并成长视频。

### 4. 角色一致性使用 Character Bible

适用：连续剧、漫剧、角色资产生成。

- 固定年龄/身份、脸型、发型发色、体型、服装、标志性配饰和动作习惯。
- 每个镜头只允许改变姿态、表情和服装状态，不随意改动识别特征。
- 角色参考词应短而稳定，关键特征重复出现，避免每镜重新发明角色。

### 5. 风格不是标签堆砌，而是行为规则

适用：所有项目风格。

- 先决定媒介材质、线条/纹理、色彩关系、光照逻辑、空间透视和运动方式。
- “真实感”由材质反馈、景深、运动模糊、环境声和有限的不完美组成，不靠无限叠加 4K、电影感等词。
- 不同风格使用不同动作与镜头语法：水墨重留白和墨晕，平面拼贴重色块和裁切，黏土重手工材质和逐格感，赛博重发光物件与空间逻辑。

### 6. 台词、音效和资产必须可验证

适用：项目视频提示词生成链路。

- 台词原样保留，并区分对白、OS、VO；没有台词明确写无台词。
- 音效只写可听见的物理声源，不用配乐替代动作音效或台词。
- 资产引用按输入映射逐一保留，禁止生成不存在的编号、故事板图或虚构资产。

## 二、项目风格推理模板架构

项目不再用代码按风格名称做固定分类。运行时按项目的 `artStyle` 直接读取对应目录：

1. 加载公共推理协议：`data/skills/production_skills/style_prompt_reasoning_default.md`。
2. 加载风格专属模板：`data/skills/art_skills/<风格>/art_prompt/prompt_reasoning.md`。
3. 加载模型硬性标签：同目录 `art_storyboard_video.md`。
4. 三层内容共同约束图片提示词推理和视频提示词推理。

新增风格时，只需在新风格视觉手册中填写“提示词推理模板”。即使暂未填写，系统也会使用公共协议和该风格自己的视频标签，不会错误套用其他风格。

### 运行时质量门与证据链

- `art_storyboard_video.md` 中每种模式的标签行既是推理约束，也是可验证契约。系统从每行前两个非通用标签提取高区分度风格锚点；最终提示词必须至少命中一个中英文锚点，只有“电影感、暖色调、高细节”等通用词不能通过。
- 风格正向锚点与冲突词、画幅、对白、关键动作、逐镜时间段和参考图标记共同构成提交前质量门。人工修改后的提示词也必须重新通过同一质量门，不能绕过。
- 每次推理保存 `promptInferenceSnapshot` schema 2，包含完整 system prompt、内容哈希、模型/模式、画幅、风格手册、参考标记、模型能力和逐镜事实。规则文件后续变化不会覆盖历史推理证据。
- 每次视频生成或任务恢复后使用媒体探针记录实际分辨率、画幅和时长，并与请求配置比较。历史视频只回填可从文件与数据库确认的 `outputAudit`，不伪造缺失的旧提示词或生成参数。

## 三、统一推理模板

```text
【风格基调】媒介/材质 + 色彩关系 + 光影逻辑 + 情绪
【主体与动作】角色/物体的固定识别特征 + 一个主动作 + 可见反应
【场景与空间】时间/天气 + 前中后景 + 关键道具 + 空间关系
【镜头与节奏】景别 + 角度 + 单一运镜 + 时间段 + 转场
【声音】对白/OS/VO 原文 + 物理音效 + 配乐（如有）
【连续性】角色、服装、道具、布局、光源、色彩和运动保持稳定
【负面约束】不新增资产；不改台词；不出现乱码/水印；不变形、不瞬移、不闪烁
```

## 四、模型适配

### Seedance 2.0

- 使用中文提示词和“图片定义 → 分镜时长 → 场景/镜头/动作/声音”的结构。
- 图片编号只在定义段声明，分镜正文使用主体/场景名称，避免编号漂移。
- 台词必须携带对白/内心 OS/画外音 VO 类型和稳定音色描述。

### 通用多参模式

- 使用 `[References]` 和 `[Instruction]` 两段。
- 参考图负责角色、场景和构图；Instruction 只补充动作、镜头、情绪、声音和时序。
- 每个片段独立保留其参考图映射，不能跨片段复用编号。

### 首尾帧/单图首帧模式

- 纯文本描述，不在正文引用 `@图N`。
- 采用 Visual / Motion / Camera / Audio / Narrative 五维结构；每个时间段至少 1 秒。
- 单图首帧优先使用叙事句，而不是关键词清单；结尾明确镜头和连续拍摄方式。

## 五、质量检查清单

- [ ] 风格锚点是否具体到媒介、材质、色彩和光照？
- [ ] 每个镜头是否只有一个主动作和明确运镜？
- [ ] 所有情绪是否都能被摄影机或麦克风捕捉？
- [ ] 角色和场景跨镜是否保持一致？
- [ ] 台词是否逐字保留并正确标注类型？
- [ ] 音效是否为可听见的物理声源？
- [ ] 时长、景别、运镜和片段数量是否匹配？
- [ ] 是否出现虚构资产、错误编号、乱码、水印或未授权文字？
- [ ] 是否按目标模型输出，而不是混用其他模型的格式？
